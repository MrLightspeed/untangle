# Worked checkout example

This runnable fixture shows how three checkout paths change when two knots are
fixed. Both source snapshots are included in this repository.

![The price route crosses quotes, orders, storage, and catalog before
untangling. Afterward, quote reaches catalog directly. Three handoffs become
one, with every file held in the same position.](../assets/example-price-route.svg)

The orange wire follows the product ID through the whole price lookup. Before,
it crosses order and storage helpers. After, it reaches the catalog directly.
The unused route owners stay visible in the same positions, so the removed
handoffs are clear. Their files remain in the project.

The [complete wiring comparison](../assets/example-comparison.svg) leads with a
route that became direct, then shows the files involved across all three
features. The example checker verifies excerpts and path references against each
snapshot and runs the shared behavior tests.

## What changed

![The read route goes from three handoffs to one and the write route carries
an order record once storage owns JSON.](../assets/untangle-banner.svg)

1. **Storage owns the JSON format.** Before,
   [orders.py](checkout/before/src/orders.py) serializes an order and appends
   the bytes. Stored rows reach [reconcile.py](checkout/before/src/reconcile.py)
   through the history and orders helpers. Reconciliation decodes those rows and
   filters pending orders. After, [orders.py](checkout/after/src/orders.py#L21)
   passes a record to `storage.write_order(order)`, and
   [reconcile.py](checkout/after/src/reconcile.py#L3) reads records directly
   from `storage.read_orders()`. Storage now owns the encoding and decoding.
2. **Price quotes look up prices through the catalog.** Before,
   [quote](checkout/before/src/quotes.py#L7) passes the product ID through the
   private [orders helper](checkout/before/src/orders.py) and
   [storage helper](checkout/before/src/storage.py#L18) to
   [catalog.price_for](checkout/before/src/catalog.py#L4). After,
   [quote calls the catalog directly](checkout/after/src/quotes.py#L10).

The feature/file map has twelve pairs before and eight after. The quote drops
its links to orders and storage. The pending report drops its links to orders
and the retired history helper. The detailed arrows show the data handed off
along each route.

## What stays the same

With the bundled `InMemoryStorage`, the shared checks cover the same callable
outputs, stored bytes and key order, validation errors, storage operation order,
pending-order filtering, and reads in both snapshots. These checks describe this
fixture only. They do not establish behavior for another storage provider.

Source links: [before storage.py](checkout/before/src/storage.py),
[old history helper](checkout/before/src/history.py),
[after storage.py](checkout/after/src/storage.py), and the
[shared behavior tests](checkout/tests/test_behavior.py).

## Run the checks

Clone or download this repository to run the example; it is not part of the
installed skill. From the repository root, use Python 3.13 or newer. No Python
packages are needed.

```sh
python scripts/check-example.py
```

The checker validates the manifest's content hashes and source locations, checks
the comparison excerpts and data paths, compiles every runtime file in memory,
and runs the same seven behavior tests against each snapshot in a separate
Python process. Those tests check callable signatures, quote results, exact
serialized bytes and key order, error types and arguments, validation side
effects, storage operation order, filtering of pending orders, and read
snapshots. The checker also confirms twelve before and eight after feature/file
pairs, regenerates the three SVGs in memory, and compares them with the saved
files. It checks that the captured PNG and its source SVG match the digests in
the capture record.

To regenerate the checked-in SVGs after changing the evidence:

```sh
python scripts/check-example.py --write-preview
python scripts/check-example.py
```

If source files change, update the affected snapshot hash and any moved line
references in [evidence.json](evidence.json). The checker prints the expected
hash when a revision is stale.

The [price route PNG](../assets/untangle-before-after.png) is a browser capture
of [the generated price route SVG](../assets/example-price-route.svg). If the
route SVG changes, capture it again with the browser viewport set to the SVG's
width and height at device scale 1. Save the PNG and update the SHA-256 digests
of both files in [preview-capture.json](preview-capture.json), then run the
checker. Review the capture visually before committing it.

## Render the interactive map

The [comparison image](../assets/example-comparison.svg) is generated by the
bundled renderer. To inspect the complete manifest in a browser, use a fresh
output directory:

```sh
python skills/untangle/scripts/render_map.py examples/evidence.json --output-dir work/example
```

Open `work/example/untangle.html`. It includes a searchable inventory of files
and edges, source locations, knot evidence, and verification records. The
manifest follows the
[wiring-map evidence contract](../skills/untangle/references/map-contract.md).

## Scope

The example contains five runtime files. Its source paths and line numbers point
to the bundled snapshots. The shared checks verify the listed behavior for those
snapshots; they do not verify behavior in another application or an agent's
ability to perform a refactor.
